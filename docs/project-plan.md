# CQUPT-SRC 项目推进计划

## 1. 当前项目判断

当前仓库是一个已经具备较完整前端界面和交互的原型项目，技术栈为：

- `React 19`
- `TypeScript`
- `Vite`
- `Express`

目前项目并不是正式后端架构，而是由一个单文件 mock 服务承载所有业务：

- 入口服务文件：[`server.ts`](/mnt/d/Code/CQUPT_SRC/cqupt-src-1.42/server.ts)
- 前端根组件：[`src/App.tsx`](/mnt/d/Code/CQUPT_SRC/cqupt-src-1.42/src/App.tsx)

## 2. 当前完成度

前端层面已经具备以下主要模块：

- 登录
- 注册
- 首页仪表盘
- 漏洞提交
- 漏洞管理
- 漏洞审核
- 用户管理
- 公告管理
- 证书管理
- 商城与兑换
- 学习中心

当前问题不在“有没有页面”，而在“后端与数据库尚未正式化”。

## 3. 已确认的现状

### 3.1 后端现状

目前所有核心数据都保存在内存数组中，包括：

- 用户
- 漏洞
- 证书
- 公告
- 学习资源
- 商城商品
- 兑换记录

这意味着：

- 服务重启后数据丢失
- 没有数据库
- 没有事务
- 没有审计能力
- 没有正式权限边界

### 3.2 鉴权现状

当前登录体系还停留在原型阶段：

- 登录时直接比对明文密码
- 登录态存在浏览器 `localStorage`
- 没有服务端会话校验
- 没有 JWT / Session / Refresh Token
- 没有接口级权限拦截

### 3.3 数据真实性现状

有些页面虽然可用，但仍然包含假数据或静态展示，例如首页统计和排行榜等，尚未接入真实聚合数据。

### 3.4 文件与上传现状

漏洞提交页面已有“附件上传”UI，但后端没有真正实现上传、存储与权限访问控制。

## 4. 技术路线建议

为了在现有代码基础上最稳地完成项目，建议继续沿用 TypeScript 全栈路线，不要大改前端框架。

建议正式技术栈：

- 前端：`React + TypeScript + Vite`
- 后端：`Express + TypeScript`
- 数据库：`PostgreSQL`
- ORM：`Prisma`
- 鉴权：`JWT` 或 `HttpOnly Cookie + Refresh Token`
- 参数校验：`Zod`
- 密码加密：`bcrypt`

## 6. 推荐开发顺序

### 第一阶段：工程底座

目标：把项目从原型改造成可正式开发的后端工程。

需要完成：

- 引入 `Prisma`
- 配置 `PostgreSQL`
- 建立 `.env`
- 拆分后端目录结构
- 迁移 mock 数据为 seed 数据

### 第二阶段：核心闭环

目标：先让平台最核心业务跑通。

优先实现：

- 注册
- 登录
- 鉴权
- 角色权限
- 用户管理
- 漏洞提交
- 漏洞审核
- 审核记录
- 积分发放与积分流水
- 承诺书签署落库

### 第三阶段：运营模块

目标：补足平台日常管理能力。

实现：

- 公告管理
- 证书管理
- 商城商品管理
- 商城兑换管理
- 首页统计真实化

### 第四阶段：正式化能力

目标：让系统可以进入稳定使用。

实现：

- 文件上传
- 附件访问控制
- 操作日志
- 参数校验
- 错误处理中间件
- 接口文档
- 单元测试与接口测试
- 部署脚本

## 7. 模型使用建议

### 适合用 `GPT-5` 的任务

- 总体方案设计
- 数据库设计
- 权限模型设计
- 审核流转与业务规则设计
- 复杂问题排查

### 适合用 `gpt-5.3-codex` 的任务

- 具体后端编码
- Prisma schema 编写
- 路由/控制器/服务层实现
- 前后端接口对接
- 批量补类型和 CRUD
- 补测试

### 不建议用轻量模型先做的任务

- 权限主设计
- 数据一致性设计
- 事务与积分逻辑
- 数据库结构定稿

## 8. 当前已发现的问题

### 8.1 依赖环境问题

当前执行 `npm run build` 失败，不是业务逻辑报错，而是本地依赖环境缺少 Rollup 可选原生包。

结论：

- 需要重新安装依赖后再验证构建
- 这不影响后续数据库和后端正式化设计

### 8.2 代码层面的待修点

已经观察到一些后续应修复的问题：

- 登录页图片路径写法不规范
- 前端存在 `confirm()` 使用
- 部分首页统计为硬编码
- 本地 `localStorage` 承担了登录态

这些都属于后续重构范围，不是当前第一优先级。
